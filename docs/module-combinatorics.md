# 模块组合与幻想载具设计

版本：2026-09-20。本文把“模块组合”从升级附属系统提升为《挖掘机拯救世界》的第一设计支柱。数量仍服从个人开发的生产上限；重点是模块之间改变行为、Prefab 轮廓、操控节奏和世界互动，而不是堆更多物品。

## 1. 设计命题

玩家不应该只说“我有 80% 更高伤害”，而应该说：

- “我把挖斗变成了会吞噬弹幕的磁暴鲸口。”
- “我用惯性飞轮把高速驾驶变成蓄力撞击。”
- “我用水炮铺出导电河道，再让电弧沿着湿润敌群跳跃。”
- “我牺牲转向和速度，把车辆变成会展开的移动堡垒。”

每次构筑选择至少改变下面一项：

1. **动作**：新增吸附、钻穿、压缩、反弹、分裂、护盾、投掷或变形。
2. **路线**：改变哪些地块值得挖、哪些敌人值得接近、是否能走捷径。
3. **节奏**：改变蓄力、过热、冷却、速度、冲刺和风险窗口。
4. **空间**：改变攻击扇面、工作半径、占地、遮挡、碰撞或模块的可见位置。
5. **修复关系**：让某种资源、污染或设施互动产生新的优势。

数值提升可以存在，但不能单独承担“组合成立”的责任。

## 2. 五类模块

模块不是统一的“加攻击卡”。每类拥有不同的操控和表现责任：

| 类型 | 作用 | 示例 | 是否改变 Prefab |
|---|---|---|---|
| 工具模块 Tool | 改变主动作的命中方式 | 宽斗、破碎锤、磁爪、钻头 | 替换工具头、碰撞探针、动作片段 |
| 动力模块 Drive | 改变移动与载荷关系 | 惯性飞轮、反重力履带、过压液压 | 增加发光部件、履带特效、震动曲线 |
| 反应模块 Reaction | 监听事件并改变局面 | 受击反弹、过热爆裂、击杀回充 | 添加护盾壳、散热片、脉冲特效 |
| 工程模块 Repair | 把修复目标转成战斗资源 | 水泵增压、净化电弧、维修无人机 | 增加管线、无人机巢、修复光束 |
| 变形模块 Morph | 改变车辆轮廓与战斗姿态 | 展开堡垒、钻地模式、空投铲翼 | 切换完整子树、碰撞配置和相机规则 |

首发只有 6 个作业副工具和 8 个辅助模块，但每个模块必须拥有一个“可见动词”。模块数量少时，用升级层、组合节点和变体参数扩展深度，不能用大量同质化卡牌稀释辨识度。

## 3. 装配拓扑

首发使用固定槽位，避免自由拼车把项目变成编辑器产品：

```text
VehicleRoot
├─ ChassisSocket
├─ ArmSocket
│  └─ ToolSocket
├─ SupportSocket_L
└─ SupportSocket_R
```

每个模块拥有 `socket_type`、`shape_class`、`mass_class`、`tags`、`requires`、`conflicts`、`visual_scene`、`action_profile` 和 `synergy_hooks`。玩家在升级界面看到的是可预览的装配后轮廓和关键行为，不需要理解内部类名。

模块组合分三层：

- **直接组合**：两个模块同时存在就产生行为，例如磁爪 + 宽斗 = 被吸附的小目标集中到挖斗扇区。
- **条件组合**：满足事件、资源或空间条件才触发，例如水炮留下湿润标签后，电弧才获得连锁跳跃。
- **转化组合**：一个模块把另一个模块的输出改变用途，例如料斗把“回收废料”转成远程碎料弹，维修无人机把“完成修复”转成护盾。

每套内容至少写出 2 个直接组合、2 个条件组合、1 个转化组合。正式版不追求所有模块两两相交，而是设计 12–16 条有意命名、有演示价值的组合边。

## 4. 操控结构

模块可以改变手感，但不能让玩家需要管理十几个主动键。输入动作保持稳定：移动、瞄准、主挖斗、投掷/倾倒、冲刺、互动、暂停。模块通过这些动作的语义变化表达差异：

| 基础动作 | 模块改变后的体验 |
|---|---|
| 按住主挖斗 | 宽斗变成扇面清障；磁爪先吸附再压缩；钻头持续推进但转向变慢 |
| 投掷/倾倒 | 普通块料变成散射、贯穿、回旋或修复弹 |
| 冲刺 | 惯性飞轮把冲刺末端变成蓄能撞击；反重力履带允许短暂跨越污染沟 |
| 受击 | 反应装甲把一次受击转成脉冲；过热模块让危险积累换取短时爆发 |
| 修复互动 | 水泵、风机或电网修复完成时触发护盾、冷却或弹药回充 |

“模块新增动作”只在一套组合拥有明确价值时出现，优先复用长按、释放、冲刺结束和命中确认等时机。所有主动效果必须在手柄上可完成，并且在模块卡片上写出输入和反馈。

## 5. 数值结构

属性计算分为不可变定义、装配修正和当局状态三层：

```text
BaseVehicle + ToolProfile
→ additive modifiers
→ multiplicative phases
→ caps / curves / conversion rules
→ runtime state (heat, cargo, cooldown, tags)
```

推荐的修正顺序：

1. 基础车体与工具的固定值。
2. 模块提供的加法值：范围、容量、基础伤害、转向、护甲。
3. 有限乘区：只允许少数明确标签进入，例如 `power`、`reach`、`tempo`，每个乘区设置软上限。
4. 转换规则：把速度转成撞击伤害、把湿润转成电弧跳跃、把修复进度转成护盾。
5. 当局状态：热量、临时增益、受伤、过热、装载量和首领阶段。

不要在装上/拆下模块时直接对当前数值反复加减；每次变更从基础值重算。所有修改带 `source_id` 和 `stack_rule`，可在结算页解释“哪两个模块造成了这次效果”。

每个模块的数值预算写成四个字段：

- **输出**：伤害、清障效率、控制或修复贡献。
- **成本**：热量、速度、转向、容量、耐久、空间或操作窗口。
- **暴露**：玩家必须承担的接近距离、预警、蓄力或资源条件。
- **放大**：它与哪些标签和事件相乘，为什么值得围绕它构筑。

这样可以避免“所有模块都只是 DPS”，并让一件强模块拥有可理解的代价。

## 6. Prefab 变化与运行时装配

定义与视觉分离：

- `ModuleDef.tres` 负责 ID、槽位、数值、标签、兼容性、触发器和 `visual_scene`。
- `ModuleVisual.tscn` 负责网格、材质、粒子、音频发射点、动画树和挂点。
- `ModuleRuntime` 负责当局状态、事件订阅和数值修正。
- `LoadoutAssembler` 按稳定槽位加载、验证、挂载和撤销模块。

装配顺序固定为：清理旧运行时效果 → 校验槽位/冲突/前置 → 实例化视觉子树 → 注册命中探针/音频/VFX 挂点 → 应用修正 → 构建组合标签 → 刷新碰撞和相机包围 → 发出 `loadout_changed`。

只有三类变化可以运行时替换：

1. **局部替换**：工具头、护甲板、散热器、天线等不改变底盘占地的部件。
2. **子树切换**：展开堡垒、钻地或飞翼等少数 Morph 模块，使用预制完整变体并冻结通行占地。
3. **参数化表现**：颜色、发光、粒子、尾迹、液压动作和音频层，不复制整个车辆 Prefab。

每次装配都必须通过“最大车体尺寸、遮挡、碰撞、导航、镜头边界、暂停/恢复、保存/加载”检查。Prefab 外观变化不能偷偷改变权威伤害或库存；玩法数据由 `ModuleRuntime` 决定，视觉只订阅状态。

## 7. Fantasy 方向

现实型号不是内容上限。挖掘机的识别来自“重型工具、伸展、铲起、搬运、破坏和修复”这些动词，外观可以大胆发展：

| 方向 | 核心幻想 | 操控/组合钩子 |
|---|---|---|
| 磁暴鲸口 | 张开巨型磁场，把废料和小型敌人吸成一团 | 吸附半径 + 宽斗压缩 + 碎料投掷 |
| 地脉钻龙 | 钻入浅层地表，从另一侧爆破出现 | 直线钻进 + 地面标记 + 破土冲击 |
| 生态方舟 | 车体携带种子、水和微型生态舱 | 修复设施 → 植被护盾 → 鸟群引导路线 |
| 折叠堡垒 | 车辆展开为移动炮台，牺牲速度换火力和抗性 | 展开/收起窗口 + 结构模块 + 受击反弹 |
| 轨道工程锚 | 把一条道路、桥或能量轨道临时拉到战场 | 路线改写 + 远距投掷 + 修复捷径 |
| 时间回收机 | 把被摧毁的碎片短暂回滚为可用资源 | 风险窗口 + 冷却 + 资源转换 |

首发只选 3 个幻想方向进入可玩内容，其余作为后续扩展或概念稿。关键是每个方向都仍然能一眼看出“它在挖、搬、砸、修”，只是把工程动作推进到玩家没有见过的尺度。

## 8. 组合设计的验收

每个模块进入量产前必须提供一张组合卡：

```text
module_id:
fantasy_sentence:
primary_verb:
base_cost:
direct_synergies:
conditional_synergies:
conversion_synergy:
input_change:
prefab_change:
audio_vfx_change:
counterplay:
test_scenario:
```

验收问题：

- 不看数值面板，玩家能否从动作和轮廓认出它？
- 装上后是否改变了至少一种路线、节奏或目标优先级？
- 是否能与至少两个已有模块形成不同性质的组合？
- 是否有清晰代价和反制，而不是无条件最优？
- Prefab、碰撞、音效、UI 图标和结算统计是否一起变化？
- 基础挖斗是否仍能完成主线，避免某模块成为必选钥匙？

## 9. 原型顺序

M0 不做完整升级池，只验证三条组合：

1. **宽斗 + 磁吸**：聚怪后压缩，证明空间控制和主斗命中关系。
2. **水炮 + 电弧**：湿润标签触发连锁，证明条件组合和状态反馈。
3. **惯性飞轮 + 冲刺**：速度转成撞击，证明操控变化和风险回报。

每条组合都要同时有灰盒视觉、输入、命中判定、数值日志、Prefab 差异、音效/VFX 和结算统计。若玩家只觉得“数字变大”，就说明组合设计没有成立，应先改行为和反馈，再增加内容。
