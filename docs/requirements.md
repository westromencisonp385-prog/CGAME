# 需求拆分：功能实现 / 表现优化

2026-09-21 · 从 [现役规格 v0.4](spec.md) 拆分。这里是执行索引，产品规则仍以 spec 为准；不是另一份平行规格，也不是已发布的 issue。

用户已确认：完整玩家流程验收、本地交付、个人 + AI + 必要外包；新增要求是整蛊、搞笑、有趣，以及先整体美学设计、确认调性后再做内容。当前代码保留为功能白模，已有测试通过不代表美术达标。

## 分类规则

- **F / 功能实现**：改变输入语义、命中、范围、碰撞、伤害、目标状态、随机选择、经济、流程或存档结果。新增 GM/自动化控制也是 F。
- **P / 表现优化**：在同一已确认结果上改变构图、模型、材质、动作演出、特效、声音、图标和界面排版。表现可关闭、替换或降低，权威结果保持一致。
- 一个体验同时需要两类时，拆成互相引用的 F/P 项。美术所需的新事件字段、挂点查询接口也单列 F 依赖，不能藏在“换皮”中。
- 例：敌人飞得更远是 F；现有落点之间的翻滚、零件晃动和落地灰尘是 P。挖斗攻击范围扩大是 F；范围不变的张嘴动作是 P。改变攻击生效时刻的 hit-stop 是 F；纯摄像机脉冲是 P。
- 所有 P 项附“参考证据 → 原创转译 → 风格约束 → 实机验收”。没有参考中的直接对应时，写明原创提案，沿用已确认的全局风格。

## 开工顺序与关口

| 关口 | 本轮/后续交付 | 放行条件 |
|---|---|---|
| G0 整体方向 | P-01 参考研究、P-02 全局美术方向、方向稿 A v2 | 用户确认整体调性；当前是待确认提案。此之前只做研究、规格和风格探索 |
| G1 镜头内样板 | 一台基础车/鲸口阶段、一个敌人、一段河岸、一个修复设施、最小 HUD | 同一真实镜头下构图、色阶、剪影和材质成体系；先看无特效画面 |
| G2 可玩表现切片 | 一个完整喜剧动作与一个修复反转；GM复现、声音和低特效版本 | 不靠解释能读懂动作因果；F/P分别验收，再走完整玩家流程 |
| G3 内容生产 | 扩三构筑、M1合同，再扩M2内容 | G2样板和生产成本通过；不能按原容量表提前批量出图/建模 |

功能上与美术方向无关的可靠性修复可以单独排期，但当前下一轮优先 G0→G1，不继续堆白模内容。风格确认只批准视觉方向，不自动批准图中所有巨大载具、敌人或合同加入首发。

## 首个可玩美术切片的拆法

选择一个场景、一条组合，把质量做出来再扩量。以下为G0通过后的顺序，不是本轮已经开始实现的承诺。

1. **P-03/P-06 场景与镜头样板**：先用大色块、正式灯光和真实比例建立河岸构图。交付无UI、无VFX的实机图，地标/道路/玩家焦点清楚。
2. **P-04/P-05 玩家样件**：同一台车的基础与鲸口阶段，实际镜头和侧视各一张；保留挂点、工作区与瞄准，关闭特效也能认出升级。
3. **P-07/P-11 对手与信息层**：一个敌人、危险区和轻量HUD；缩至720p仍读得清，场景不再被测试说明面板压住。
4. **F-05/F-12 功能差额**：仅补打包/释放规则和表现事件缺口。先验证目标资格、资源/伤害不重复、存档与取消，再接演出。
5. **P-08/P-09/P-10/P-12 喜剧演出**：以同一功能结果制作30秒“聚拢→鲸口打包→投掷→修复”的连续演出；正式碰撞时刻与声画一致。
6. **F-14/F-15 验收**：GM复现同一场景，捕获有/无VFX、修复前后与读档后结果；实际试玩确认笑点、爽感和操作仍可理解。

每项完成记录包括：需求ID、类型、输入证据、交付文件、构建/版本、验收场景、结果与遗留问题。P通过不能自动关闭对应F；F通过不能自动关闭P。新的色板或轮廓偏离已确认方向时，先回到P-02更新方向，不在单件资产里悄悄改全局风格。
