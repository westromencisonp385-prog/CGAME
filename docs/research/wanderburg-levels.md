# Wanderburg 关卡研究（C28，2026-10-10）

证据：原作 `data.unity3d` 中 77 个 WaveSpawner（每关的刷怪导演）、14 个 LocalSpawner（营地刷怪点）、9 个 BiomeData、1694 个 Agent 的序列化值，以及 il2cpp 反编译类定义。提取脚本 `tools/asset_pipeline/re_extract_levels.py`，原始结果 `wanderburg-levels.json`。

## 一局的结构

- 一个群系 = 一局，一局分 4 个阶段（WaveSpawner tier 0~3），每阶段有自己的 Boss。群系难度 1~5，银币倍率 1.0~1.5。
- 每阶段参考时长 240~320 秒，Boss 在 160~240 秒出场（约 70% 处），加时从 320~420 秒开始。阶段内打死 Boss 就进下一阶段，拖太久就进加时。
- Boss 血量按阶段递增：草原 2100、5500、7000、9500。

## 一个阶段内部：四条刷怪线并行

| 刷怪线 | 原作字段 | 做什么 |
|---|---|---|
| 全局涓流 | `totalAgentPool` + `troopSpawnIntervalOverTimeCurve` + `troopSpawnStrengthOverTimeCurve` | 每隔 9 秒（后期缩到 6 秒）从敌人池抽一组，组大小乘以强度曲线。池里每种敌人有解锁时间和稀有度（common / uncommon / rare） |
| 预设波次 | `preProgrammedWaves` | 按时间点写死的关键节拍，大多从玩家前进方向刷出 |
| 中立波次 | `neutralPreProgrammedWaves` | 羊群、房子、风车（可吞的成长食物），还有逃跑的宝箱车、回血补给车、磁铁补给车 |
| 蜂群事件 | `swarmEventWaves` | 阶段中段（约 80~120 秒）一次大潮：一个大家伙 + 上百杂兵从两侧对冲而来，有预警 |

另外还有加时（`overtimePreprogrammedWaves` + `overtimeAgentPool`）：刷怪间隔从 13 秒压到 2.6 秒，刷的是 1800~5000 血、速度 56~120 的“清场者”，逼玩家去打 Boss。

强度曲线的形状（tier 0）：开局 1.0，到 70% 涨到 1.3；Boss 出场那一刻跌回 1.0（让玩家专心打 Boss），最后 10% 涨到 2.0。tier 3 是 1.12 → 1.8 → 1.0 → 2.3。

## 敌人配比

| 角色 | 血量 | 数量 | 例子 |
|---|---|---|---|
| 杂兵（Unit） | 5~30 | 一组 12~50，蜂群 120~180 | 弓手 5 血、长枪兵 30 血、骑兵 20 血 |
| 威胁（Vehicle） | 400~1150 | 一次 1~4 个，按时间点出 | 炮塔 600、攻城锤 800、自爆车 410、霰弹坦克 1150 |
| 重型 | 4500~10000 | 偶尔 1 个 | 巨炮步行者 4500、脱粒机 10000 |
| Boss | 2100~9500 | 每阶段 1 个 | |

杂兵一碰就死，靠数量制造割草爽感；威胁是少量、写死时间、有名有姓的对手；Boss 是阶段高潮。杂兵和威胁的血量相差约 40~100 倍。

## 刷怪位置

刷怪模式有 6 种：surround（包围）、randomDirection（随机方向）、doubleOppositeSideRandom（两侧对冲）、allDirections（四面）、playerDrivingDirection（玩家前进方向）、groupSurround（分组包围）。

- 预设波次九成用“玩家前进方向”：敌人从你要去的地方出现。
- 刷怪距离 120~250 米，远在镜头外；Boss 和玩家至少隔一段距离，优先刷在屏幕外。
- 营地刷怪点（LocalSpawner）在玩家进入一定距离后开门放兵，有上限，带门动画。

## 对我们的启示

1. 地图太小：原作刷在镜头外，我们的场地只比一屏大一点，敌人只能“凭空出现在眼前”。
2. 没有节奏：我们只有开局摆好的 5 个敌人加 F4 手动刷，没有涨落、没有高潮、没有喘息。
3. 没有杂兵：我们最弱的小怪也要 2~3 口，割草爽感出不来；精英和小怪只差 6 倍。
4. 没有中立目标：原作的宝箱车、补给车、可吞建筑会制造“追不追、绕不绕”的路线选择。
5. 敌人太慢：我们小怪每秒 1~2 米，玩家每秒 7 米，纯 WASD 永远甩得掉，没有压迫感。
