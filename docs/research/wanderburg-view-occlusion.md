# Wanderburg 视角与遮挡研究（C26，2026-10-10）

证据来源：原作 `data.unity3d` 序列化数据（提取脚本 `tools/asset_pipeline/re_extract_view*.py`，原始结果 `wanderburg-view-occlusion*.json`）、il2cpp 反编译类定义、Steam 商店 12 张实机截图（`artifacts/research/wanderburg_ref/`，仅研究用）。

## 原作怎么做

| 项 | 原作（实测） | 我们（C26 前） | 结论 |
|---|---|---|---|
| 投影 | 正交（Main Camera `orthographic=1`，size 16.3，CameraRig 按档 39/45/56/72） | 正交 | 一致 |
| 俯角 / 朝向 | 相机挂在 CAMERA_RIG 下，本地旋转 (45°, 0, 0)，位置 (0, 200.2, -200.2) | 45°、yaw 0 | 一致 |
| 裁剪面 | near 100 / far 1000，离场景 ~283m | 离场景 60m | 正交下不影响透视；无需改 |
| 景物尺度 | 树、房、墙都比玩家城堡矮或相当；截图里载具和敌人永远是画面主体 | 树 3.4m、杨树 1.7m、墙 1.1m、风车 2.6m，玩家车 ~1.2m | **问题 1：景物比车高 2~3 倍** |
| 高物件位置 | 树林、悬崖都在地图外圈远处，玩家和镜头之间（画面下方）几乎没有高物件 | 镜头一侧（南）边界整排高树 + 大石 | **问题 2：近镜头侧高物件盖住可玩区** |
| 遮挡后显示 | 用 Quick Outline（`Outline.Mode` 含 OutlineHidden / SilhouetteOnly），EPO 描边挂在 7 个模块 Skin 上；FlatKit 描边 + 平面边缘光 | 无 | **问题 3：躲到景物后面完全看不到自己** |
| 散布资产 | GPU 实例化 | MultiMesh 散布丢了 GLB 根节点缩放、还把隐藏网格画出来 | **问题 4：同一种树散布版和摆放版大小不一** |

正交 45° 下的遮挡关系：一个高 h 的物体在屏幕上会往上（远处）盖住约 h 米的地面。景物比车高 2~3 倍时，车开到树 / 墙后面就整个看不见，这就是“遮挡关系不对”。透视本身（投影和俯角）与原作一致，问题出在世界尺度和摆放。

## 我们的改法

1. 世界高度规则 `WorldDressing.WORLD_HEIGHT`：每种景物定目标高度（树 1.25~1.45m、墙 0.5m、灯杆 0.95m、风车 1.6m……），实测可见网格后只缩不放；墙 / 路障类只压高度保持占地，其余等比缩小。
2. 摆放：镜头一侧（南 +Z）和左右两侧南半段只放灌木，高树留北侧；大石不放南侧。
3. 遮挡淡出 `OcclusionFader`：挡在玩家 / 敌人 / Boss 和镜头之间的景物，屏幕空间判定，0.08s 一次，平滑淡到 25%。
4. 被挡剪影：RigStyle 给玩家（暖骨白）和敌人（番茄红）加深度比较剪影 pass，只在真被别的东西挡住的像素上画。
5. 散布修正：MultiMesh 带上 GLB 根变换、跳过隐藏网格，散布与摆放同尺寸。

验收：`game/tests/c26_view_audit.gd`（高物件盖住可玩区 < 3%、正交 45° yaw 0、全部 60 件资产无躺倒 / 浮空、躲到景物后它会淡出、角色带剪影 pass）。C26 前 221 m²（可玩区 21.7%）→ 后 20.4 m²（2.0%）。
