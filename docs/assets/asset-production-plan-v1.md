# Reclaimer 资产生产方案 v1

日期：2026-09-26。本文是模型、动作、敌人、精英和 Boss 的生产入口。它把“概念设计 → Weaver 服务 → Blender 修整 → Godot 验收”串成一条可回查的流程。

## 1. 产品视觉和 fantasy 边界

本作保留的是**工程动词**：铲、吸、压、扔、钻、拖、焊、修复；外形不再受现实挖掘机限制。玩家机器可以成长为鲸口巨兽、移动工厂、折叠桥城或超大型施工机器人，只要玩家能看懂它改变了哪一个工程动作、操控代价和战术路线。

视觉目标是**工业童话低多边形**：大负形、歪斜但有功能原因的机械结构、哑光色块、少量手绘笔触、强轮廓和夸张比例。禁止用金属噪声、螺栓堆积、泛光和通用科幻面板制造“完成度”。风格锚点和验收规则见 [style-lock-industrial-folk-v1.md](style-lock-industrial-folk-v1.md)。

尺度分三层：

- 普通敌人：一个行为剪影，玩家 3 秒内读懂。
- 精英：普通行为加一个会改变空间或资源的大件，最多两只同屏。
- Boss：超出玩家车体 1.8–3 倍的大型失控设施或机器人，至少两阶段；阶段改变路线、规则或修复目标，不能只增加血量。

## 3. 资产包合同

每件正式资产必须有以下文件或记录：

1. 概念输入图、来源、SHA256、风格版本和提示词。
2. 可编辑 Blender 源文件或可复现脚本。
3. GLB/FBX、材质槽、独立可动部件、命名枢轴、碰撞代理和 LOD0/1/2。
4. 状态表：基础、预览、安装、执行、受击、损坏、修复；设施还要有施工态。
5. 动作表：动作名称、准备/接触/余韵帧段、权威事件、停止条件和 VFX/SFX 挂点。
6. Blender 转台截图、Godot 真实镜头无 VFX 截图、720p/1080p 检查和缺陷复测记录。
7. 生产 manifest：API 任务 ID、输入/输出 hash、Blender/Godot 版本、许可证和验收状态。

模型、动作和挂点必须按 [weaver-production-queue.json](weaver-production-queue.json) 的稳定 ID 管理。状态只使用：`planned → concept_locked → authored_control → api_candidate → review → integrated`。

## 4. Weaver 的正确位置

Weaver 是异步 3D 服务层，不是最终美术作者。完整边界见 [weaver-api-purpose.md](../api/weaver-api-purpose.md)，完整原文见 [weaver-api-docs.md](../api/weaver-api-docs.md)，可执行 Skill 见 [Weaver Skill](../../.agents/skills/weaver-asset-production/SKILL.md)。

### 允许的调用顺序

1. **图像输入**：清理成单主体、无文字、无道具的参考图；图生360（7）补齐四视图。
2. **形体候选**：图生高模（3）或中模（11）只生成草模候选；不直接接入 Godot。
3. **几何处理**：UV（9）、重拓扑（1/10）、LOD（2）和贴图（8）逐阶段提交，逐阶段下载和检查。
4. **角色化动作**：只有服务支持的模型才尝试骨骼（5）→蒙皮（6）→动作（4）。骨骼输入必须是文档要求的 FBX zip 和正确 JSON；失败就停，不猜参数。
5. **机械动作**：鲸口、泵阀、桥体、液压臂优先由 Blender/Godot 枢轴和关键帧完成。文本生动作只能作为候选，不能替代 F-12 权威事件。

### 已验证的边界

- A01 Weaver 高模候选：保留大嘴轮廓，但为单网格、无 UV、无动作，拒绝作为最终资产。
- 作者化 B01/C04 控制资产：分别为 660/740 三角、5/6 材质，并保留命名动作。
- B01 通过正确的 FBX + `model.json(config.mesh_category, config.algo_name, selection)` 成功骨骼架设；蒙皮成功。
- B01 文生动作任务返回 `991002`，因此正式机械动作保留 Blender 动作；失败记录在 [b01_motion/report.json](../../artifacts/weaver/api_candidates/b01_motion/report.json)。

## 5. Blender 和 Godot 生产分工

### Blender 负责

- 大形、负形、拆件、父子关系、枢轴、骨骼、材质槽、碰撞代理和 LOD 最终调整。
- 精英/Boss 的装甲拆解、阶段显隐、弱点部件和可复用动作。
- 导出前删除随机零件、错误材质、浮空部件和与功能无关的细节。

### Godot 负责

- 实时材质参数、预告线/扇/环/网格、粒子、镜头、UI、声音和修复前后环境变化。
- 订阅 F-12 权威事件；动画不改变伤害、碰撞、载荷、路线或存档结果。
- 低画质降级、暂停/慢放/读档一致性和真实游戏镜头验收。

## 6. 敌人和 Boss 的统一动作合同

共享状态：`idle / move / telegraph / attack / stagger / engineering_countered / defeat / retreat`。

共享挂点：`EnemyRoot`、`TelegraphOrigin`、`TelegraphAim`、`Contact`、`Weakpoint_*`、`VfxAnchor_*`、`Sfx_*`、`Drop`、`RepairTarget`。

每次攻击必须有：

- 准备：拉开主负形，显示攻击方向和退路；
- 接触：由权威事件触发命中或空间改变；
- 余韵：回弹、失衡、错误施工或喜剧道具反应；
- 反制窗口：玩家能说出“我为什么成功/失败”。

普通敌人只教一个工程动词；精英把两个约束叠在一起；Boss 把机器谱系、群系规则和修复结果放进同一场合同。

## 7. 生产关口

| 关口 | 必须通过 | 产物 |
|---|---|---|
| G0 风格 | 大形、色板、负形、比例、材质和 fantasy 方向明确 | 风格锚点、输入模板、反例清单 |
| G1 样板 | 一车、一普通敌人、一设施、一段河岸同镜头成立 | 无 VFX 实机图、模型包、碰撞/挂点检查 |
| G2 喜剧动作 | 准备→接触→余韵可读，规则和动作同步 | 30 秒连续片段、有/无 VFX 对照、声音占位 |
| M1 敌人梯度 | 4 普通、1 精英、1 Boss 能完成同一合同 | 预告/反制矩阵、Boss 修复结果、存档恢复 |
| M2 超大幻想 | Boss 外形超出挖掘机范畴但仍可操作、可读、可修复 | 代表机器、精英、Boss 和群系完整切片 |
