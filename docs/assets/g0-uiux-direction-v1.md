# G0 UIUX 方向 v1：工业童话工单

日期：2026-09-27。状态：`proposal` / `whitebox`。用户已确认 G0 的整体调性为**工业童话**；本文是 UIUX 重做的方向与验收合同，不批准当前 Godot 界面进入正式资源。

![G0 UIUX 与渲染方向板（提案，不是最终资源）](g0-uiux-industrial-folk-v1.png)

## 1. 范围与不变的玩法合同

本文只规定信息层级、页面状态、焦点路径、战场避让、装配预览和失败/恢复反馈。玩法权威、碰撞、命中、资源、修复、奖励和存档仍由现有游戏状态决定，UI 不得反过来决定它们。

玩家流程保持：

> 出击 → 驾驶/工程动作 → 改装 → 预览 → 确认 → 回到战场验证组合 → 升级/变形 → 合同胜负 → 检查点恢复。

当前 `game/scripts/m0_hud.gd` 的 HUD、改装台、按钮、结果面板、提示文字和 GM 面板均为**白模**；当前程序化车体、模块幽灵和现有卡面也不能被 UI 包装成正式美术。本文通过 G0 后，才可以把同一套信息结构交给视觉与实现制作。

实现事实基线：

- `main.gd` 有 `outcome=active/won/failed` 与 `garage_open/manual_pause` 等可观察流程字段；F5 保存、F9 恢复，恢复失败时保留当前出击。
- `LoadoutAssembler` 维护核心位、动力位、功能位 A/B、结构阶段，以及独立的 `preview_id`；预览不能改变实装状态，确认才写入装配。
- 现有控制映射为：WASD/左摇杆驾驶，鼠标/右摇杆瞄准，左键/RT 作业，右键/LT 投掷，Shift/LB 冲刺，R/A 修复，B/Y 改装，Esc/Menu 暂停。
- GM 面板是开发测试工具；它可以调用同一状态接口，但不能冒充正式 HUD，也不能出现在正式玩家截图的主信息层。

## 2. 工业童话的界面语法

界面像一张认真填写、却经常遇到荒唐故障的工程工单：厚纸板或烤漆铭牌的分区、钉住的标签、粗体动作词和少量手绘箭头。笑点来自信息与机械结果的关系，例如打包敌人后盖上“已分类”，不靠贴满表情或连续弹窗讲笑话。

### 2.1 视觉规则（提案）

| 项目 | G0 规则 | 反例 |
| --- | --- | --- |
| 主色 | 工程黄 `#E9AD38`、石油蓝 `#253D48`、骨白 `#EEE3C7`；危险珊瑚红 `#DF604E`；磁能灰紫 `#A486DB`；修复水青 `#58B7AC` | 彩虹渐变、所有状态都发光、环境与玩家同色 |
| 面板 | 低透明度深底 + 清楚边界 + 小范围纸张/铆钉提示；面板是信息容器，不是整屏遮罩 | 玻璃拟态、无边界的深色矩形、通用科幻面板 |
| 图标 | 工作头剪影 + 一个动作符号；缩小时先读形状再读颜色 | 细线图标、只靠颜色区分、概念图上的英文小字 |
| 文案 | 先写动词和结果：`吸入`、`接触`、`修复`、`路线已通`；笑话放在结果的第二拍 | 长教程段落、状态只显示数值、用模糊的“可用/不可用” |
| 动效 | 准备 → 接触 → 余韵三拍；确认、错误和恢复各有固定节奏 | UI 动画改变命中时刻、无限抖屏、关键字被粒子盖住 |

### 2.2 信息优先级

所有页面按同一优先级组织，不允许因为装饰或 GM 信息挤掉工作区：

| 层级 | 玩家必须在何时看到 | 内容 | 默认呈现 |
| --- | --- | --- | --- |
| H0 权威结果 | 每帧/每次状态变化 | 是否可操作、危险、当前目标是否完成、预览是否可确认 | 高对比标签、图形状态 + 短文案 |
| H1 关键资源 | 战斗决策前 | 耐久、载荷/热量、当前合同目标、修复/路线状态 | 固定锚点，数字与单位同组 |
| H2 操作上下文 | 玩家准备动作时 | 当前工作头、瞄准方向、装载/冷却、可用工程动作 | 靠近对应状态区的短提示 |
| H3 反馈余韵 | 结果发生后 2–4 秒 | `威胁解除`、`水泵启动`、组合名称、失败来源 | 不遮挡战场的短卡/字幕，自动退场 |
| H4 开发信息 | 仅测试/开发 | GM 开关、冻结、调速、预设、调试 ID | 独立 GM 面板；正式 HUD 永不显示 |

没有模态面板时，不透明 UI 在 16:9 画面中目标覆盖率低于 18%；先满足 H0/H1，再显示 H2/H3。全屏装配与结算页可以占用更多空间，但必须保留明确的焦点和返回路径。

### 2.3 概念图是视觉真源

本轮 UI 的色板、材质暗示、明暗对比、轮廓密度和幽默比例以已确认的**工业童话概念图**为视觉真源。概念图负责回答“这个世界应该看起来怎样”；Godot 材质、渲染器、字体和控件只负责把这套规则稳定地实现到真实镜头中。

| 来源 | 可以决定 | 不能证明 |
| --- | --- | --- |
| 用户确认的 G0 概念图/方向板（如 [方向 A v2](art-direction-a-v2.png)） | UI 主色与状态色的关系、纸张/烤漆/橡胶的材质暗示、主体与背景的价值对比、形状密度与留白、工业童话的幽默比例 | 真实碰撞、工作范围、动态光照、性能、字体最终尺寸 |
| [整体美术方向](art-direction.md) 与 [工业童话风格提案](style-lock-industrial-folk-v1.md) | 将概念图转成可执行的色板、材质家族、三档明暗和 G1 镜头检查 | 已完成正式模型或已锁定全部 UI 资产 |
| 当前运行截图、`m0_hud.gd`、程序化几何和幽灵方块 | 现有状态、输入、流程和避让问题的证据 | 任何目标美术品质；不得作为配色、材质、渲染或布局样板 |

当前渲染和白模截图全部不合格，不能被“加贴图、加发光、换字体”包装成正式资源。G0 UI 样板必须回到概念图的色板与明暗关系重做；在真实 Godot 镜头中关闭 VFX 仍要保留概念图要求的主体/背景对比、危险/修复状态对比和足够留白。概念图上的文字、标语和具体比例仍是风格提示，正式文字由可本地化 UI 绘制。

## 3. 页面与状态规范

### 3.1 状态总表

| 状态 ID | 进入条件 | 主信息 | 可执行动作 | 退出条件 |
| --- | --- | --- | --- | --- |
| `battle.active` | 合同正在进行且未暂停 | 耐久、载荷/热量、合同目标、路线/修复、当前动作 | 驾驶、瞄准、作业、投掷、冲刺、修复、打开改装、暂停、保存/恢复 | 改装、暂停、胜负、有效恢复 |
| `battle.feedback` | 权威事件已发生 | 保留 H0/H1；显示一条 H3 结果短卡 | 继续操作；必要时按提示重复动作 | 2–4 秒后退场，或被更高优先级事件替换 |
| `garage.select` | 按 B/Y 或对应菜单动作打开改装台 | 当前装配、模块卡网格、目标槽位 | 浏览模块、切换槽位、查看模块详情 | 选中模块进入预览、取消返回战场 |
| `garage.preview.valid` | 合法模块已选中 | 安装前/后剪影、动作变化、收益/代价、组合条件、目标槽位 | 确认安装、切换模块/槽位、取消 | 确认写入装配，或取消清除预览 |
| `garage.preview.invalid` | 重复、挂点不兼容或缺少条件 | 具体冲突原因与修复建议；实装保持原样 | 更换模块/槽位、取消 | 选择合法候选或返回战场 |
| `pause` | Esc/Menu；改装打开时按返回关闭改装 | 继续、恢复检查点、设置、退出本次出击（若该动作已获批） | 仅菜单焦点可操作，世界暂停 | 继续或完成恢复 |
| `result.won` | 修复与威胁等合同条件完成且奖励写盘成功 | 完成目标、修复结果、蓝图/永久进度、下一步 | 重新出击、恢复检查点（若仍可选）、返回 | 新出击或恢复成功 |
| `result.failed` | 工程车失去动力或合同失败 | 主要受伤来源、失败原因、当前构筑贡献、检查点是否可用 | 重新出击/换构筑、恢复检查点 | 重试或恢复成功 |
| `recovery.success` | 有效检查点通过验证并恢复 | 恢复了装配、资源、敌人、修复状态；回到哪个状态 | 继续出击；可再次打开改装 | 返回 `battle.active` 或结果页 |
| `recovery.blocked` | 无检查点、损坏检查点、版本/校验不通过、写盘失败 | 说明失败原因；当前出击和旧检查点都不被覆盖 | 关闭提示、继续当前出击或重试写盘 | 用户关闭或下一次恢复尝试 |
| `gm.open` | F1 或开发入口 | GM 状态、预设、冻结/调速/资源、独立存档 | 仅开发操作；清楚标记 `开发测试` | F1/关闭回到原状态 |

`battle.feedback` 不是新的玩法状态；它只是 H3 的显示状态。UI 不得因为显示动画而暂停权威模拟，也不能将“准备”字幕当成已经命中。

### 3.2 战场 HUD 布局

首个实机样板只保留四组固定锚点：

1. **左上：工程车铭牌**：耐久、载荷/热量和当前工作头；变化时只高亮变化字段。
2. **右上：现场工单**：当前合同目标、回收/威胁计数、水泵状态、路线状态和计时；目标顺序由“现在要做什么”到“做完后会怎样”。
3. **底部安全条**：只显示当前可用的关键动作和输入；可由玩家缩放/关闭，不显示 GM 指令。
4. **事件短卡锚点**：H3 卡固定在屏幕上缘或下缘的安全槽，不跟随敌人/玩家漂浮到工作区中央。

当状态变化时，数字、形状和文字至少有两种同时变化；禁止只用红/绿颜色区分。当前 UI 的 `RECLAIMER / 回收者`、`工单 01`、资源条、改装按钮、提示条可作为信息清单参考，但外观全部回到 `whitebox` 重新设计。

## 4. 手柄焦点与输入路径

### 4.1 总原则

- 任何可见、可操作菜单均有唯一焦点环；焦点环使用骨白外轮廓 + 当前状态色，不用只变亮度。
- 打开模态页后焦点被限制在该页；焦点不能穿透到战场或背后面板。
- `A/RT` 只确认当前焦点，`B/LT` 返回上一级；`Menu/Esc` 在战场打开暂停，在改装页优先取消预览/关闭改装。
- 禁用按钮不进入焦点链；无效模块仍可聚焦，但必须显示具体原因，避免玩家以为它被漏掉。
- 焦点移动不改变装配；只有“确认安装”才提交 `LoadoutAssembler.confirm_preview()`。
- 焦点顺序与视觉阅读顺序一致，横向网格优先左右，跨行时上下；焦点循环不得跳进 GM。

### 4.2 具体路径

| 起点 | 默认焦点 | 方向键/摇杆路径 | 确认 | 返回 |
| --- | --- | --- | --- | --- |
| `battle.active` | 无菜单焦点；操作提示显示当前动作 | `B/Y` 打开改装，`Menu` 打开暂停 | `A` 修复（满足条件时） | `Menu/Esc` 暂停 |
| `garage.select` | 第一张可预览模块卡；已有装配仍可看但标 `已安装` | 模块卡网格 → 槽位选择 → 预览详情 → 操作按钮 | `A` 选模块；合法后进入预览 | `B` 关闭改装并清除预览 |
| `garage.preview.valid` | `确认安装` | `LB/RB` 在模块候选间切换；上下在详情、槽位、确认/取消间移动 | `A` 提交；提交后焦点回到战场动作提示 | `B` 清除预览，装配不变 |
| `garage.preview.invalid` | “换模块/换槽位”建议动作 | 回到卡片或槽位，不允许跳过冲突信息 | `A` 只执行修正动作 | `B` 取消并保留原装配 |
| `pause` | `继续出击` | 继续 → 恢复检查点 → 设置 → 退出（若存在） | `A` 执行 | `B/Menu` 关闭暂停 |
| `result.won/failed` | `重新出击 / 换构筑`（成功页可先聚焦奖励确认） | 重新出击 → 恢复检查点 → 返回 | `A` 执行 | `B` 返回上一级（如该流程允许） |
| `recovery.blocked` | `关闭` 或 `继续当前出击` | 错误详情 → 重试 → 关闭 | `A` 执行 | `B` 关闭，不丢当前状态 |
| `gm.open` | GM 页首个开发控件 | 仅在 GM 控件内循环 | `A` 执行开发命令 | `B/F1` 关闭 |

G0 通过前，不把当前 `module_buttons[0].grab_focus()` 或结果页 `Retry.grab_focus()` 视为最终焦点设计；它们只能证明白模流程可走通。最终实现须在 720p、1080p、键鼠和手柄各走一遍上述路径。

## 5. 战场避让合同

### 5.1 保留区与避让区

屏幕坐标以安全框为准，默认留出 5% 外边距；UI 面板不得压过以下动态区域：

| 区域 | 判定 | UI 规则 |
| --- | --- | --- |
| 玩家工作区 | 主车体、工作头、瞄准方向前方约一车长至工作范围 | 固定 HUD 不进入；动作短卡只在屏幕安全槽显示 |
| 敌人危险区 | 预告方向、冲撞线、投掷落点、危险区边界 | 不放目标文本或按钮；使用场景标记/轮廓传达危险 |
| 修复设施与路线 | 水泵、桥/捷径、当前可走退路及其入口 | 工单卡显示状态，但路线本身必须可见；禁止覆盖入口 |
| 载荷落点 | 投掷目标与落点前后短时区域 | 反馈卡不跟随落点遮挡；余韵效果可在落点外缘出现 |
| 镜头边界 | 斜俯视正交视野的可玩安全框 | 不把重要信息放到会随跟镜头裁切的位置 |

### 5.2 动态避让策略

- H0/H1 固定在四个安全槽；只有 H3 事件卡可在上缘/下缘两个槽之间切换，避免覆盖工作区。
- 场景中的危险和目标用几何标记、轮廓和方向表现，不用漂浮大字压住实体。标记必须与权威目标/危险方向同步。
- 面板打开时停用所有会与面板重叠的战场操作；背景仍可见但不能偷走焦点。
- 车辆最大阶段、敌人预告、修复前/后均须各截一张无 VFX UI 避让图；如果 UI 遮挡退路，优先改锚点/镜头安全框，不缩小关键字到不可读。
- UI 视觉装饰不改变物理碰撞、工作范围、敌人命中或路线门禁；任何需要改变包络的视觉资产另列玩法/碰撞变更。

### 5.3 通过门槛

- 关闭 VFX、贴图和声音，玩家仍能指出目标、危险、工程解法和至少一条退路。
- 128 px 缩略图能读出玩家车、普通敌人和修复设施的主行为剪影；UI 不把它们切成孤立小块。
- 720p 与 1080p 文字不互相遮挡，工作头接触、修泵交互和路线开闭均有清楚可见区域。

## 6. 装配与预览

### 6.1 预览的单一真相

预览使用当前装配快照的副本计算候选结果，实装仍由 `LoadoutAssembler` 权威保存。预览阶段必须满足：

1. **同一辆车**：左/主视图显示安装前轮廓，右/叠加视图显示候选轮廓；驾驶室、底盘和已装模块保持可识别。
2. **同一工作区**：幽灵模块使用正式网格/挂点合同，不另造一套只在 UI 中成立的碰撞或动作。
3. **同一动作**：卡片先写一个动作动词，再写会改变的操控、路线、节奏或修复关系；数值只是补充。
4. **同一条件**：明确槽位（核心/动力/功能 A/B）、替换对象、重复/冲突原因和组合触发条件。
5. **同一结果**：确认前不改变资源、冷却、碰撞、敌人状态或存档；取消后幽灵消失，原装配和焦点上下文恢复。

### 6.2 模块卡字段

每张卡按以下顺序显示，字段没有值时显示“未定义”，不隐藏成空白：

| 顺序 | 字段 | 示例语法 | 必须回答 |
| --- | --- | --- | --- |
| 1 | 工作头剪影 | `宽斗 / 颚口 / 水炮` | 它装在车的哪里？ |
| 2 | 动作动词 | `聚拢并压缩` | 玩家会做什么不同的事？ |
| 3 | 操控/路线变化 | `前方吸附范围扩大；转向更慢` | 手感和退路如何变？ |
| 4 | 组合条件 | `磁吸目标 → 载荷投掷` | 与现有模块怎样联动？ |
| 5 | 收益与代价 | `范围 +1.0；速度 -0.8` | 为什么要取舍？ |
| 6 | 槽位与替换 | `功能位 A；替换水炮` | 会不会覆盖既有装配？ |
| 7 | 预览状态 | `预览 / 已安装 / 冲突 / 缺条件` | 现在能否确认？ |

当结构阶段从 1 变为 2 时，预览必须显示新增负形、关节和代价；不能只换颜色或加发光。预览标题不使用“最终”“正式资源”等词，直到 G0/G1 视觉验收通过。

### 6.3 确认与取消反馈

- 合法预览：确认按钮显示即将提交的槽位和替换对象；按下后先显示“安装中”的短暂准备，再在 `loadout_changed` 后显示“模块已安装 · 回到战场试试”。
- 非法预览：按钮不可确认；错误文案说明“重复模块”“挂点不兼容”“需要先完成某条件”之一，并给出下一步。
- 取消：清除幽灵、恢复原装配、焦点回到触发的模块卡或槽位，不出现“安装成功”反馈。
- 组合提示：只在权威事件首次触发时显示一次名称 + 结果；组合未触发时不要用装配页文案暗示已经生效。

## 7. 失败、保存与恢复反馈

### 7.1 反馈语法

每条错误都回答“发生了什么、当前是否安全、下一步是什么”。使用图形（警告/检查/锁）+ 文案 + 状态色，不只用红色。错误卡不清空玩家已确认的装配或当前检查点。

### 7.2 失败/恢复矩阵

| 事件 | 玩家看到 | 可做什么 | 权威状态要求 | 验收证据 |
| --- | --- | --- | --- | --- |
| 重复模块/不兼容槽位 | `此模块已安装` / `此模块只能装在功能位`；指出目标槽位 | 换卡、换槽、取消 | `preview_id` 可清除；装配不变 | 截图 + `LoadoutAssembler` 状态前后相同 |
| 预览资源/条件不足 | `还差 3 单位废料` 或明确缺失条件 | 回战场收集、取消 | 不得伪造可确认按钮 | 条件不足时确认不可达 |
| 合同失败 | `工程车失去动力`；列出主要伤害来源与构筑贡献 | `重新出击 / 换构筑`、`恢复检查点` | `outcome=failed`；重试不覆盖检查点 | 失败页 + F9 恢复截图 |
| 合同胜利 | `河岸已重获生机`；列出修复、威胁清除、蓝图 | 继续结算、重试、恢复（若仍提供） | 奖励写盘成功后才进入 `won`；重复结算不重复奖励 | 奖励 ID 与页内状态一致 |
| F9 无有效检查点 | `没有有效检查点，当前出击保持不变` | 关闭并继续 | 当前世界、装配、资源不变 | 操作前后快照相同 |
| 检查点损坏/校验失败 | `检查点不可用；旧检查点已保留` | 关闭、继续当前出击、选择另一备份（若有） | 不覆盖最后一个完整检查点 | 损坏文件 + 恢复后状态证据 |
| 保存失败 | `保存失败，原检查点保留` | 重试保存、继续 | 旧检查点可读取；不标记为已保存 | 失败注入 + F9 验证 |
| 蓝图奖励暂时写盘失败 | `蓝图写盘失败 · 合同暂不结算，稍后自动重试` | 继续等待或返回安全状态 | 不进入已领奖胜利；重试幂等 | `campaign_reward_pending` 复现 |
| 改装中按返回 | `预览已取消`（可选短卡） | 回战场 | `preview_id` 清空，实装不变 | 取消前后装配快照对比 |
| GM 操作造成测试状态 | 明确 `开发测试` 标签 | 关闭 GM、恢复正常检查点 | GM 存档与正常进度分开 | 正式 HUD 无 GM 文案 |

当前结果页的“重新出击 / 换构筑”和“恢复检查点”是白模按钮；新 UI 可以改变排版和文案，但必须保留上述语义、幂等性与状态边界。
