日期：2026-09-27。用途：建立本项目高质量体验切片的外部参考基准。本文只记录观察和原创转译，不把外部资产复制进游戏。

## 2. Steam 页面直读

本轮直接读取 [Wanderburg Steam 商店页](https://store.steampowered.com/app/3624140/_Wanderburg/)。页面把产品承诺写成：移动城堡、吞噬村庄、模块化攻城武器、每局实验不同 build、局外解锁模块/车辆/神器/船长，并强调城堡会扩张而不是只加倍率。页面还展示了单人、控制器和等距/俯视标签，以及当前 Early Access 的核心循环和 build variety 目标。

这些是产品级参考事实，不代表我们可以复制其资产或算法。它们给本项目的质量要求是：玩家必须一眼看到“我这局长成了什么”，每个模块必须改变机器结构、机制或战场关系，升级卡必须能解释 build 的行为差异。

## 3. 从解包图像和页面截图观察到的质量

### 模型与材质

- 车辆不是一块色块；车体、城墙、炮塔、履带、门、烟囱、驾驶/操作件有明确层级和可解释的重复结构。
- 共享色板、半哑光材质、黑色/深色接触面、边缘线和局部磨损一起承担可读性；材质差异不靠随机噪声。
- 成长通过增加体块、炮塔、烟囱、侧翼和负形实现，玩家在俯视镜头仍能读出规模变化。
- 大件有厚度、阴影和接触关系；空腔、门、炮口和轮组不是平面贴图。

### 场景与渲染

- 关卡不是一块平面；地面色块、树簇、农田、道路、建筑群、烟、阴影和边界共同建立空间层次。
- 轮廓阴影和接触阴影很重，主体和背景有明确价值对比；雾、雨、烟和粒子服务空间关系。
- 关键目标、敌人和升级对象拥有更高的画面对比和更完整的局部细节，普通地面保持低频以给操作留空间。

### UI 与构筑

- 升级界面用统一的边框、字体、图标、按钮和材质语法；卡片本身就解释模块是什么、装在哪里、会做什么。
- 图标不是通用符号换色，而是对应炮塔/建筑/能力的独立剪影；能力文字、自动攻击和资源关系成组呈现。
- 多种模块与载具形态在商店图和页面截图中都保留可识别的独立身份，这正是本项目 100+ build 目标需要达到的视觉方向。

## 4. 当前项目截图对标结论

当前 Godot 截图 `artifacts/qa/capture-20260927-064214-447/repair.png` 与 `built.png` 仍存在明显差距：

- 关卡是低密度几何块和单色地面，缺少参考中的建筑、道具、材质层、阴影和空间叙事；
- A01/B01/C04 候选模型能加载，但实机镜头内尺寸、姿态、状态和材质信息不足；
- HUD 仍是开发面板，缺少参考中的统一卡片、图标、字体、焦点路径和信息节奏；
- 候选手绘图集和 VFX 图集尚未完成 UV/材质/粒子接入；
- 当前截图可以证明流程、导入和事件运行，不能证明达到 Wanderburg 质量。

因此当前 G1 仍是 **failed / candidate**，不能宣称高质量完成。

## 5. 重新制定的对标顺序

1. 用新鲜 AssetRipper 导出重新建立玩家车、模块卡、特效图集、字体、色板、阴影和场景层级的研究矩阵。
2. A01/B01/C04 绑定 UV、手绘表面图集、损坏/修复材质与状态显隐，保持概念图的颜色和结构关系。
3. 重做倒流河谷的前景/中景/背景、桥、泵站、管线、树簇、地面材质和修复后远景。
4. 重做 HUD、装配卡、预览对比和修复结算，使机制签名、成本、反制和视觉差异同屏可读。
5. 同一真实镜头输出无 VFX、有 VFX、修复前/中/后、720p/1080p 对照图，再决定是否关闭 G1。

AssetRipper Free 导出和 Steam 页面只证明可观察的资源组织、视觉和产品描述，不证明 Wanderburg 内部算法、运行时数值或可复制的实现。正式资源必须重新创作；当前项目仍以原创概念图和本报告的质量要求为指导。
