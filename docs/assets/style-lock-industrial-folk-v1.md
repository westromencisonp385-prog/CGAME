# 工业童话低多边形风格锁定（v1）

日期：2026-09-26。用途：冻结 Weaver 输入、Blender 建模和 Godot 实机检查的共同视觉规则。它是当前生产设定，不把任何一张概念图当作最终 3D 资产。

## 先解决什么问题

上一轮高模输入是常见的“精致工业玩具”：表面磨损、螺栓和光泽很多，轮廓、关节和幽默比例反而不突出。这类输入容易生成看似完成、但没有作者意图的模型。v1 改成**工业童话低多边形**：让大形、偏斜比例和手绘色块承担身份，把细节压到能支持动作的位置。

风格锚点见 [style-anchor-industrial-folk-v1.png](style-anchor-industrial-folk-v1.png)。这张图只证明形状语言和色彩方向；尺寸、碰撞、模块接口和动画仍由 Blender/Godot 合同决定。

## 形状规则

- 玩家车的注意力分配为：鲸口负形 60%、驾驶室和底盘 20%、关节/服务件 20%。
- 物体优先使用 6–20 面的厚板、楔形、短圆柱和不对称支撑；每个装饰件必须解释一个功能。
- 保留**歪斜但可解释**：左右不对称来自液压支撑、维修面板、配重或工具接口；不使用随机扭曲。
- 鲸口只有少量大牙和清楚的黑色空腔。空腔必须从正交斜俯视镜头读出来，牙齿不能堵住工作区。
- 驾驶室是共同身份锚点；阶段变化扩大工具头/负形/关节，不把驾驶室换成另一种车。
- 敌人用一个行为剪影：B01 的横向蟹脚、宽挡板和大警示灯比细节重要。
- 设施用一个可操作剖面：C04 的泵体、密封环、阀轮、压力表和两端管口必须能分别进入状态表。

## 色彩、材质和光线

基础色只从六类共享色板取值：石油蓝、赭黄、骨白、番茄红、灰紫、橡胶黑。一个资产最多 5 个主材质槽，发光只用于磁环/修复状态。

模型使用哑光或半哑光顶点色/简单材质。磨损只保留少量手绘笔触，不能生成连续噪声、随机锈斑或贴满边缘的划痕。阴影用三档明暗表达体块；Godot 的灯光和接触阴影负责实时变化，概念图里的高光不能烘入贴图。

## Weaver 输入和输出

生成前先把概念板整理为单主体、无文字、无道具的输入；输入图只负责风格锚点和轮廓。优先使用 Weaver 图生360得到四视图，再以实际四视图调用图生高模/中模。输出必须经过 UV、纹理（如确有收益）、LOD 和 Blender 检查；任务成功不能替代验收。

每件资产的生产包必须包含：

1. 输入图及 SHA256、实际生成工具和版本记录。
2. Weaver model/task ID、请求参数、轮询终态和本地下载 hash；报告中不保存签名 URL 或凭证。
3. GLB/FBX、源模型或可复现脚本、材质槽、拆件和挂点说明。
4. LOD0/LOD1/LOD2、独立碰撞代理、状态表和动作接口。
5. Blender 转台截图、Godot 真实镜头无 VFX 截图、720p/1080p 检查和缺陷记录。

## 风格验收

资产只有同时满足以下条件才可进入 `review`：

- 缩到 128px 仍能读出主剪影和工程动词；缩到实际斜俯视镜头仍看见危险和退路。
- 大形不依赖纹理噪声；关闭材质贴图和 VFX 后仍像同一台原创机器。
- 每个运动件都有明确父子关系、枢轴和事件；装配预览与实战使用同一网格。
- 玩家车的嘴、斗、驾驶室和工作区不挡 HUD/目标；敌人的预告姿态不会被挡板或特效遮住。
- 模型导入无错误，面数、UV、材质槽、碰撞和 LOD 落在资产队列范围内。
- 动作按“准备 → 接触 → 余韵”三拍验收；权威事件决定接触时刻，动画不能改玩法结果。

## 明确不做的视觉决策

本 v1 不使用写实工程车比例、电影级镜头光晕、通用科幻面板、密集小螺栓、角色脸、随机贴纸、概念图文字或无法解释的漂浮部件。它们会削弱玩家对工程动作、模块差异和喜剧因果的理解。
