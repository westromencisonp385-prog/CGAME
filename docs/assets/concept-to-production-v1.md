# 概念图到正式资产的还原计划 v1.1

日期：2026-09-28。状态：执行计划。图形漫画方向 C 已确认，首轮磁暴流派开始内容生产。正式资产必须还原已确认概念图的结构、比例、材质分区、动作姿态和状态变化；当前 Godot 白模与旧 GLB 不得直接升级为正式资源。

本计划遵守 [项目全局指导](../project-guidance.md)：风格化、高精度、去 AI 感，以及每个机制 build 都有对应的结构和视觉表现。

## 本轮风格与交付身份

- **图形漫画方向 C**：强轮廓、硬色块、夸张透视、非对称剪影、漫画式速度/打击形状和作者控制的材质笔触共同形成识别度。禁止把风格简化成低多边形、统一工业玩具、连续噪声或随机 AI greeble。
- **概念 PNG**：设计真源，负责造型、剪影、色材、动作意图、敌人职责和 Boss 阶段；不进入运行时，不冒充模型或截图。
- **3D candidate**：由 Blender、程序工具或 Weaver 生成的模型、材质、骨骼、动作候选；必须保留拆件、枢轴和意图表，允许评审和导入试验，不能直接标记 `integrated`。
- **真实游戏集成**：在 Godot 实际相机和目标画质中通过碰撞、动作事件、材质状态、LOD、UI 避让、波次复现和缺陷复测；本轮尚未完成。

## 首轮生产目标：15 分钟磁暴流派

这一轮先做一条完整的从小到大的流派，不扩全量战役。目标为约 15 分钟：

| 阶段 | 形态 | 资产重点 | 实机体验 |
|---|---|---|---|
| 1. 磁暴鲸口·幼体（0:00–4:00） | 小型履带作业体，短距磁吸、基础颚口、投送 | A01 基础剪影、颚口枢轴、磁力预告、N01–N03 | 先读懂工程动作，再完成聚拢和投送 |
| 2. 移动回收工厂（4:00–10:00） | 后段展开回收舱，磁环和压缩结构出现 | A01 展开件、压缩舱、E01/E02 反制姿态、N04 维修链 | 高速清怪、重击和物理连锁形成主爽点 |
| 3. 超大型吞噬机械（10:00–15:00） | 上下颚、磁环、回收舱扩大为战斗巨械 | 巨型剪影、动态拉远、BOSS01 三阶段、镜头 UI 避让 | 以击败断城巨神本体结束战斗；战后再展示修复 |

试制起点与波次、敌人职责、升级分支和局外解锁见 [现役产品规格](../spec.md) 的“首轮已确认内容”章节。这里的生成输出必须逐项关联到波次和动作，不生产只用于转台展示的孤立模型。

## 建模要求

### A01 磁暴鲸口

- 以深石油蓝履带作业体作为起点，但允许车体逐步脱离现实挖掘机比例，保留赭黄驾驶舱和骨白上下颚的巨大负形；终局要读成超大型吞噬战斗机械。
- 上颚、下颚、磁环、液压臂、驾驶室、左右履带、模块接口必须独立拆件。
- 三阶段剪影要在同一谱系上可见：鲸口幼体、移动回收工厂、超大型吞噬机械；成长必须依靠结构展开、模块轮廓和动作尺度，不能只靠缩放。
- 口腔、牙齿和紫色磁环是视觉重点；碰撞代理排除装饰牙齿，工作区必须可读。

### B01 施工蟹

- 以概念图的橙白路障板、红色警示灯和四腿横移姿态重做，避免当前红色楔形白模。
- 左右挡板、腿、警示灯、锚点和反向牌独立拆件；横向冲刺必须有可读姿态。
- 材质使用手绘磨损和大色块，文字由 UI/贴花系统单独处理，不能把概念图文字烘进贴图。

### C04 修复泵

- 以概念图的黄蓝泵体、压力表、阀轮、密封环和管口重做，保留剖面阅读顺序。
- 停机、施工、恢复三态共享碰撞和挂点，改变的是显隐、材质、流体和桥/水流表现。
- 表情和喜剧姿态可作为表现层，但不能替代压力、阀门和修复状态的读法。

### 首轮敌人与 Boss

所有敌人先做概念 PNG，再做 3D candidate；每个候选必须同时给出待机、攻击预告、接触/命中、受击和撤退或死亡姿态。不要先做只有一个正面转台图的模型。

| ID | 资产 | 必须保留的图形漫画识别点 | 首轮动作与战斗证据 |
|---|---|---|---|
| N01 | 路障蟹 | 路障板、横向夹脚、警示色块 | 放障、夹逼、侧后暴露；磁吸拖离或压缩 |
| N02 | 刀轮废料犬 | 不对称刀轮、低伏高速剪影、夸张旋轮 | 绕侧、旋轮冲撞、被撞硬直 |
| N03 | 炮虫 | 埋地炮管、红色抛物落点、短粗弹体 | 埋地、预告、发射、被投送打断 |
| N04 | 维修蜂 | 维修束、蜂巢工具包、成群连线 | 维修链、短暂护盾、被优先清除 |
| E01 | 雷炉河马 | 大散热炉、厚重前甲、短腿蓄势 | 蓄电、直线冲锋、撞空后的侧后弱点 |
| E02 | 浮环猎手 | 悬浮环、反磁脉冲、长矛牵制 | 绕圈、反磁、浮环被打掉后失去反制 |
| BOSS01 | 断城巨神 | 城墙式肩架、断裂施工臂、可见核心 | 铆臂下砸→盾架与召援→吞城冲锋暴露核心；三阶段均需预告、可攻击窗口和受击余韵 |

Boss 资产必须优先验证战斗可读性：巨型结构不能遮住核心、危险区或玩家退路；镜头拉远只服务空间判断，不替代清晰的扇区预告。Boss 被击败后才进入 C04/河岸修复演出，修复不改变 Boss 的战斗胜利条件。

## 贴图与材质

- 每件首批资产先交付颜色块材质，再交付手绘磨损、边缘高光和功能件细节；不使用连续噪声掩盖结构。
- A01 共享石油蓝、赭黄、骨白、番茄红、灰紫、橡胶黑色板；B01 加橙白路障与红灯重音；C04 加黄蓝设施与青绿修复状态。
- 金属度、粗糙度、法线和发光分层保存，Godot 运行时材质只负责状态参数，不能改变玩法判定。
- 贴图必须去除概念图文字、箭头、边框和排版，只保留原创绘制的表面信息。

## 首批美术量下限

为了避免只做一个漂亮模型，首批 G0/G1 包至少包含：

- A01：基础、张口磁吸、压缩释放 3 个剪影状态；驾驶室、左右履带、上下颚、磁环、液压臂、模块接口 7 组可拆件；6 类共享材质和 1 套磨损/警示贴花。
- B01：待机、横移预告、筑墙、侧冲、受击、反制、撤退 7 个动作状态；左右挡板、四腿、警示灯、锚点和反向牌独立拆件；墙体和锚点各 1 套可复用变体。
- C04：停机、施工、恢复 3 个设施状态；泵体、压力表、阀轮、密封环、进/出管口、蒸汽与水流 6 组表现层；桥、管道、路标、碎石、湿地植被 1 套河岸环境道具包。
- 首轮敌人/Boss：N01–N04、E01–E02、BOSS01 各 1 套概念 PNG、3D candidate、动作状态、危险预告和战斗检验场景；BOSS01 需要三阶段弱点和动态镜头拉远对照。
- UIUX：战场 HUD、装配卡、预览对比、暂停/设置、合同结算 5 个页面状态；模块图标、状态图标、危险/修复标记和手柄焦点样式各 1 套。

## 渲染重做

- 先建立统一场景灯光：主方向光、冷色环境填充、接触阴影、受控雾和修复状态色；不靠泛光制造完成度。
- 真实镜头先验收图形漫画轮廓、工作区、目标、危险区和退路，再加入磁环、电弧、尘土、碎片和喜剧余韵；关闭 VFX 仍要读懂战斗。
- UI 与世界使用同一色板和对比度规则；HUD 不覆盖颚口、敌人预告、泵站阀门或桥的通路。
- 形态变大时镜头动态拉远，拉远阈值和 UI 安全区必须随真实波次验证；不能用固定转台图代替实机镜头。
- 每个资产交付 Godot Mobile 的无 VFX、状态对照和 720p/1080p 截图；当前白模截图只作为问题记录。

## 生产顺序

1. 从三张概念 PNG 抽取比例、拆件、色板、材质、挂点、动作和漫画式打击形状清单。
2. 为磁暴鲸口三阶段和 N01–N04/E01–E02/BOSS01 制作概念 PNG 分镜，先过轮廓、危险方向和反制审查。
3. Blender/程序/Weaver 生成 3D candidate，保存源文件、版本、hash、拆件和动作阶段；Weaver 只用于局部形体/材质探索。
4. Godot 建立真实镜头、动态拉远、灯光、材质状态、碰撞、LOD、敌人波次和 UI 避让样板。
5. 先完成 A01 一车一模块和 N01–N04 的战斗片段，再接 E01/E02 与 BOSS01 的同镜头三阶段对照；通过 G1/G2 后才标记 `integrated`。

## 验收边界

- 当前白模与旧 GLB 不计入正式资源完成度。
- 概念图还原不等于游戏内验收；必须通过真实镜头、无 VFX、状态切换、碰撞和 UI 避让检查。
- 概念 PNG 只标记 `proposal`/`source`，3D candidate 只标记 `candidate`；未通过 G1/G2 的资产不得标记为 `integrated` 或 `final`。
- BOSS01 必须在真实波次中证明三阶段的预告、弱点、受击余韵和击败结算；漂亮的概念图或转台图不能代替 Boss 战斗验收。
