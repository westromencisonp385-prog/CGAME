# 核心玩法循环审计

日期：2026-09-22。审计对象是当前 M0，而不是把规格中的 M1/M2 内容提前包装成完成。

## 结论

**M0 核心循环成立，可以继续扩展；不需要因为基础手感链路失败而重做方向。**

当前可运行的闭环是：

1. 接近废料或敌人。
2. 用铲斗完成工程动作，获得装载资源或改变敌人状态。
3. 收集材料让车辆进入二阶段。
4. 进入改装台选择合法构筑。
5. 用磁暴鲸构筑把轻型目标聚拢、打包，再一次释放。
6. 携带材料启动水泵，世界进入修复状态。
7. 清除威胁并完成合同。
8. 保存、读取或重试，状态仍然一致。

公共 seam 测试为 core_loop_flow.gd，以玩家动作和 main.gm.execute/get_state 为观察入口；它不是对私有方法的镜像测试。当前固定 Godot 4.7.2 的全套测试也包含 whale_pack_flow.gd、contract_flow.gd、save_flow.gd 和 presentation_flow.gd。

## 证据

| 环节 | 当前结果 | 证据 |
|---|---|---|
| 工程动作→材料 | 通过；重复主作业会击毁目标并产生资源 | core_loop_flow.gd |
| 材料→阶段成长 | 通过；达到阈值后进入阶段 2 | core_loop_flow.gd、m0_smoke.gd |
| 构筑→组合 | 通过；磁暴鲸要求宽斗+磁吸，轻型目标可打包 | whale_pack_flow.gd、真实 whale.png |
| 组合→一次释放 | 通过；释放按瞄准方向落点并防重复结算 | whale_pack_flow.gd |
| 材料→修复 | 通过；靠近水泵并满足资源后修复状态变化 | contract_flow.gd、真实 repair.png |
| 修复→合同出口 | 通过；修复和威胁清除共同完成合同 | contract_flow.gd、core_loop_flow.gd |
| 存档→继续 | 通过；装配、载荷、敌人状态和修复可恢复 | save_flow.gd、whale_pack_flow.gd |
| 表现开关 | 通过；关闭 VFX 不改变权威结果 | presentation_flow.gd |

## 尚未成立的商业循环部分

这些是 M1/M2 的缺口，不是 M0 失败：

- 修复后的捷径目前主要是状态和视觉反馈，还没有一张有明确绕行成本的正式路线图。
- 合同胜利后的蓝图/永久奖励、营地服务和下一次出击解锁尚未完成。
- 改装台当前能预览和确认模块，但升级奖励还没有完整地从合同结算进入下一局。
- 三个机器谱系、正式怪物行为、首领和三群系尚是世界圣经中的提案。

因此下一刀应做一个完整 M1 小合同：至少有一处必须绕行的修复路线、一个可领取蓝图、回到营地后的可见服务变化，再重跑同一闭环。当前不新增第四套机器或更多怪物来掩盖这几个缺口。

## 体验优化规则

任何新增内容都必须回答：玩家做了哪个工程动作、改变了哪一个权威状态、获得了什么可读收益、下一次出击如何因此不同。笑点和 VFX 只能放大这个因果，不能替代它。若新增内容不能通过同一公共 seam 或真实 GPU/试玩证据，就保持为设定提案。
